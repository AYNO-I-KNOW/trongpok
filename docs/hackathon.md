# Regional Codex Hackathon Thailand — Sea × OpenAI

**21 พฤศจิกายน 2026 · เวลาไทย (ICT, UTC+7)**  
เริ่มพัฒนา **10:25 น.** · **17:00 น. หยุดแก้โค้ดและปิดรับผลงาน ส่งช้าถูกตัดสิทธิ์**

## กรรมการตัดสินอย่างไร

กรรมการให้คะแนนจาก **สิ่งที่ทีมสร้างและสาธิตให้เห็นว่าทำงานจริง** ไม่ใช่จาก pitch อย่างเดียว เอกสารผู้จัดระบุ 6 เกณฑ์ แต่ไม่ระบุน้ำหนักหรือคะแนนเต็มรายข้อ

| เกณฑ์ | กรรมการดูอะไร | สิ่งที่ trongpok ควรแสดง |
|---|---|---|
| Problem & Solution Fit | ปัญหามีจริงไหม และวิธีแก้ตรงปัญหาหรือไม่ | สินค้าดาวสูงอาจไม่เหมาะกับงานที่ผู้ซื้อจะใช้จริง เช่น เครื่องปั่นที่ไม่เหมาะกับการปั่นน้ำแข็งเปิดร้าน |
| Build Quality | ระบบทำงานจริงและรับมือการใช้งานได้ไหม | เดโมตั้งแต่รับโจทย์จนถึงผลจัดอันดับ เปิดหลักฐานให้ตรวจย้อน แสดงเมื่อข้อมูลไม่พอ และเตรียมโหมดกฎหาก API ใช้ไม่ได้ |
| Insight & Originality | วิธีแก้ต่างจากสิ่งที่ใช้กันทั่วไปอย่างไร | เปลี่ยนรีวิวให้เป็นหลักฐานรายข้อที่ผู้ซื้อต้องการ ให้ Skeptic หารีวิวที่ค้าน และให้โค้ดคำนวณอันดับ |
| Real-World Value | จากเดโม ใครได้ประโยชน์ และมากแค่ไหน | แสดงว่าผู้ซื้อหลีกเลี่ยงตัวที่ไม่ผ่านข้อจำเป็นหรือประหยัดได้เท่าไร ใช้ผลที่วัดได้จริง ไม่อ้างว่าลดการคืนสินค้าแล้ว |
| Alignment with Build Direction | สิ่งที่สร้างสอดคล้องกับอย่างน้อยหนึ่งแนวทางอย่างมีสาระไหม | ใช้ **AI-Native Products & Operations** เป็นแนวทางหลัก: ผู้ซื้อถามว่าสินค้าเหมาะกับการใช้งานของตัวเองไหม แล้วตรวจคำตอบกับรีวิวได้ |
| Use of Codex | ใช้ Codex ลงลึกแค่ไหนในการสร้างผลงาน | เตรียมตัวอย่างที่ตรวจได้ว่า Codex ช่วยสร้างหรือทดสอบอะไร โดยใช้ [ชุด prompt](codex-prompts.md) และ commit ที่เกี่ยวข้อง ไม่ใช่แค่บอกว่าแอปเรียกโมเดล OpenAI |

## ผู้จัดอยากเห็นอะไร

เลือกอย่างน้อยหนึ่ง Build Direction แล้วแสดงให้เห็นว่าแนวทางนั้นอยู่ในสิ่งที่ทีมสร้างจริง:

- **Autonomous & Adaptive AI** — เอเจนต์ทำงานได้อย่างน่าเชื่อถือโดยไม่ต้องมีคนคอยกำกับตลอด และดีขึ้นเมื่อทำงานมากขึ้น
- **AI-Native Products & Operations** — ใช้ AI เปลี่ยนวิธีทำงานหรือออกแบบผลิตภัณฑ์ใหม่ จนผู้ใช้หรือธุรกิจทำสิ่งที่ก่อนหน้านี้ทำได้ยากหรือไม่คุ้มในทางปฏิบัติ
- **Deep Domain AI** — สะท้อนวิธีทำงานจริงของผู้เชี่ยวชาญจนผู้เชี่ยวชาญไว้ใจให้ช่วยงานได้ ไม่ใช่เพียงจำลองแบบย่อ

สำหรับ **trongpok** ให้เริ่มจากการตัดสินใจซื้อจริง: ผู้ซื้อมีข้อจำเป็นและงบ ระบบหาหลักฐานทั้งสนับสนุนและคัดค้าน ก่อนเสนอทางเลือกที่อธิบายได้ว่าผ่านข้อไหนและต้องยอมเสียอะไร

## สิ่งที่ต้องส่ง

ส่ง **หนึ่งครั้งต่อทีม** ผ่าน [Google Form](https://forms.gle/8exwHfkf1TLfFDha6) ภายใน **17:00 น.** (ลิงก์จาก QR ในสไลด์ *Project Submissions* หน้า 17)

- [ ] **GitHub repo:** ลิงก์ repo ใหม่ที่ตั้งเป็น public และสร้างสำหรับงานนี้
- [ ] **Project write-up:** สรุปปัญหา วิธีแก้ แนวทางที่ตรงกับผลงาน และวิธีที่ทีมใช้ Codex
- [ ] **Demo link:** ลิงก์ live demo หรือ prototype
- [ ] **Declarations:** ระบุโปรเจกต์ open source หรือโปรเจกต์ส่วนตัวเดิมที่นำมาใช้ และแยกให้ชัดว่าส่วนไหนสร้างขึ้นในงานนี้

งานทั้งหมดต้องทำที่หน้างาน กรรมการประเมินเฉพาะสิ่งที่สร้างระหว่าง hackathon เริ่มใหม่หรือต่อยอดงานเดิมก็ได้ แต่ถ้าต่อยอด ต้องเพิ่มงานใหม่อย่างมีนัยสำคัญ ใช้ repo public ใหม่ และใส่ลิงก์ repo ต้นทางพร้อมระบุส่วนที่สร้างในงานทั้งใน README และฟอร์มส่งงาน การฝ่าฝืนอาจถูกตัดสิทธิ์
