# ชุดข้อมูลเดโม

ทีมเตรียมเองทั้งหมด ห้ามคัดลอกชื่อสินค้า คำอธิบาย หรือรีวิวจาก Shopee (ToS ข้อ 3.1) และห้ามใช้ข้อมูลจาก `spike/` หรือ `price-spike/` ใช้ ChatGPT ร่างรีวิวจากสถานการณ์ที่ทีมกำหนดได้ แต่ต้องอ่านแก้ทุกอัน ช่วงเช้าวันงานให้แจ้งกรรมการว่าเป็นข้อมูลสังเคราะห์ที่เตรียมมาก่อน

## ไฟล์

| ไฟล์ | คืออะไร |
|---|---|
| `categories/<id>.json` | คำถามแบบปุ่มของหมวดนั้น แต่ละตัวเลือกคือ requirement ที่ระบบตรวจ มี `blender`, `smartwatch`, `bird-repeller`, `car-damping` |
| `products/_example.json` | ตัวอย่างครบทุกฟิลด์ ระบบข้ามไฟล์ที่ขึ้นต้นด้วย `_` |
| `products/<id>.json` | สินค้า 1 ชิ้นต่อไฟล์ |
| `personas.csv` | โจทย์ผู้ใช้กับอันดับที่คนจัด ใช้วัดผลบนเวที |

## จำนวนขั้นต่ำ

| หมวด | สินค้า | รีวิวต่อชิ้น | persona | เรื่องที่หมวดนี้เล่า |
|---|---|---|---|---|
| blender | 6 | 15–25 | 2 | สเปกบอกว่าได้ แต่ผู้ใช้จริงบอกว่าไม่ได้ |
| smartwatch | 6 | 15–25 | 2 | ฟีเจอร์ต้องตรงคนใช้: คนออกกำลังกายกับผู้สูงอายุได้คนละรุ่น |
| bird-repeller | 4 | 20–30 | 1 | ยอดขายกับดาวมาจากรีวิวชมลอยๆ แลกเหรียญ และรีวิวตอนแกะกล่อง |
| car-damping | 4 | 15–25 | 1 | ของพังหลังเดือนที่ 3 แต่รีวิวปิดหลัง 30 วัน |

สินค้าหมวดอื่นเพิ่มได้ ให้หน้าแรกดูมีของหลากหลาย แต่ไม่นับในการวัดผล หมวดใหม่ต้องมี `categories/<id>.json` ด้วย

## ออกแบบสินค้าให้ arena มีเรื่องเล่า

ในแต่ละหมวดต้องมีครบทุกแบบ:

- **ดาวสูงแต่ไม่เหมาะ**: 4.8★ ขายดี แต่ requirement สำคัญถูกรีวิวแย้ง เช่น สเปกบอกว่าปั่นน้ำแข็งได้ แต่รีวิวบอกว่ามอเตอร์ไหม้ (ดู `_example.json`)
- **แบรนด์ดังราคาแพง**: ผ่านทุกข้อ แต่ `features` ส่วนใหญ่ไม่ตรงกับคำถามใดเลย (ทำให้เห็นตัวเลขประหยัด)
- **ตัวคุ้ม**: ราคากลางหรือต่ำ ผ่าน must ทุกข้อ และมีรีวิวยืนยัน
- **ตัวที่หลักฐานบาง**: รีวิวที่พูดถึงเรื่องสำคัญน้อยกว่า 10 รีวิว ต้องขึ้นว่าข้อมูลไม่พอ
- **ตัวที่สเปกไม่ระบุ**: ไม่มี key ที่คำถามใช้ เพื่อให้ web search (S10) มีงานทำ หรือขึ้นว่า `unknown`

รีวิวในแต่ละชิ้นต้องมี: ดาวสูงแต่บ่น, บ่นขนส่ง, ประชดหรือแสลง ("ปกเทพ", "จกตา"), ชมลอยๆ และรีวิวสำเร็จรูป (`isTemplate: true`)

เขียนระยะเวลาที่ใช้ไว้ในข้อความรีวิวเอง ระบบอ่านจากข้อความ ไม่มีฟิลด์แยก:

- **แกะกล่อง**: "เพิ่งได้รับ ยังไม่ได้ลอง แพ็คดีค่ะ" / "แกะกล่องแล้วสวยมาก"
- **ใช้ไม่กี่วัน**: "ลองมา 3 วัน นกยังไม่มา"
- **ใช้นาน**: "ใช้มา 4 เดือน ช่วงแรกได้ผล ตอนนี้นกกลับมาเกาะเหมือนเดิม" / "ติดไป 3 เดือน หน้าร้อนแผ่นเยิ้มไหลลงขอบประตู กลิ่นฉุนในรถ"

### bird-repeller

- ตัวขายดีสุด: 4.9★ ยอดขายสูงมาก แต่รีวิวกว่า 70% เป็นแบบ "ดีค่ะ ใช้ได้ผล แนะนำ" "เพิ่งได้รับ ส่งไว" ซึ่งเป็นรูปแบบของรีวิวแลกเหรียญ มีรีวิวใช้นานไม่กี่อันที่บอกว่านกกลับมา
- ตัวที่ได้ผลจริง: ดาวต่ำกว่า เช่น 4.4★ (บางรีวิวบ่นติดตั้งยาก) แต่มีรีวิวใช้นานที่ระบุชนิดนกกับสถานที่
- ใส่ claim จากการไลฟ์ (`source: "live"`) เช่น "ไล่ได้ทุกชนิด 100%"

### car-damping

- ตัวเคสจริงของทีม: 4.8★ รีวิวช่วง 30 วันแรกชมว่า "ประตูปิดเสียงแน่นขึ้น" แต่สเปกไม่ระบุ `heatResistC` ใส่รีวิวใช้นานแค่ 1–2 อันที่บอกว่าเยิ้ม (สะท้อนว่าคนส่วนใหญ่รีวิวไม่ทัน) และใส่ claim จากไลฟ์ (`source: "live"`) เช่น "ทนความร้อน ไม่ละลาย" กับ "ประตูละ 4 แผ่น"
- ตัวที่ระบุ `heatResistC` ชัด (butyl + ฟอยล์) ราคาแพงกว่า แต่มีรีวิวใช้นาน

## ฟิลด์สินค้า

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | ตัวพิมพ์เล็กคั่นด้วยขีดกลาง ตรงกับชื่อไฟล์ |
| `category` | ต้องตรงกับ `categories/<id>.json` |
| `specs` | key ต้องตรงกับ `spec.key` ในคำถามของหมวด |
| `features` | ฟีเจอร์ที่ขายอยู่ ใช้คำนวณ "ฟีเจอร์ที่จ่ายแต่ไม่ได้ใช้" |
| `shopeeUrl` | เว้นว่างได้ ถ้าว่าง ปุ่มเปิดใน Shopee จะไปหน้าค้นหาด้วยชื่อสินค้า |
| `stars`, `ratingCount` | ตัวเลขที่ Shopee โชว์ ใช้เป็น baseline |
| `claims[].source` | `title`, `description`, `variant`, `video` หรือ `live` (คำพูดในไลฟ์หรือแชตของร้าน) |
| `claims[].checkable` | `false` เมื่อรีวิวพิสูจน์ไม่ได้ เช่น ของแท้ หรือทองแดงแท้ |
| `reviews[].isTemplate` | รีวิวสำเร็จรูป ระบบตัดทิ้ง |
| `reviews[].daysAgo` | อายุไม่เกิน 90 วันได้น้ำหนักเพิ่ม |

## persona (`personas.csv`)

| คอลัมน์ | ตัวอย่าง |
|---|---|
| `persona_id` | `b1` |
| `category` | `blender` |
| `need_text` | `จะเปิดร้านกาแฟเล็กๆ ต้องปั่นน้ำแข็งวันละ 50 แก้ว` |
| `link_product_id` | ว่างได้ ใส่ id สินค้าเมื่อ persona นี้เริ่มจากการวางลิงก์ (ใช้ทดสอบ Verifier) |
| `answers` | `use=ice;volume=cap-large;budget=3000` แต่ละคำถามใช้ id ของ requirement ที่เลือก ถ้าเลือกหลายข้อให้คั่นด้วย `+` ส่วนงบใช้ตัวเลข คำถามที่ข้ามหรือเลือกตัวเลือกที่ไม่มี requirement ไม่ต้องใส่ |
| `labeler_a_top3`, `labeler_b_top3` | `blender-x>blender-y>blender-z` สองคนจัดแยกกัน ห้ามดูของอีกคน |
| `human_top3` | อันดับหลังคุยกันแล้ว รูปแบบเดียวกับ top3 ข้างบน |
| `must_notes` | สินค้าที่คนเห็นว่าไม่ผ่าน must พร้อมเหตุผลสั้นๆ คั่นด้วย `;` |

`personas.csv` มีโจทย์ 6 แถวให้แล้ว ทีมต้องเติมอันดับ และสร้างสินค้าที่ `link_product_id` อ้างถึง (`blender-smoothie-pro` คือ `_example.json` ที่เปลี่ยนชื่อไฟล์, `car-damping-live-hit` คือตัวเคสจริงของทีม)

จดอัตราที่ top-1 ของสองคนตรงกันไว้ ตัวเลขนี้คือเพดานที่ระบบทำได้
